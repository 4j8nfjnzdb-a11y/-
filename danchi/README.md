# 団地 DANCHI

同じ一つの音（物）を、置かれる場所と隣との関係だけで違って鳴らす生成楽器。
物は FM の音のほか、WAV / MP3 の一部、入力（Fireface などのオーディオインターフェイスやマイク）、いま鳴っている自分の音（生成変化）からも作れる。
その上に、切り替えられる別の層として、部屋ごとのエフェクト（グリッチ・ディレイ・ピッチ・スタッター・逆再生）と、サイコロがある。
ブラウザで動く試作と、そのまま小さな機械（M-VAVE FM-1 / fm1-base）へ持っていくための C コア。

- 試作: `index.html`（HTTP で開く。`file://` だと AudioWorklet が読めず、遅い代わりの経路になる）
  例: リポジトリのルートで `python3 -m http.server 8000` → `http://localhost:8000/danchi/`
- 中身は一つの C コア（`core/`）。ブラウザはそれを WebAssembly にして AudioWorklet で動かす。
  同じ種・同じ操作なら、ネイティブ版とブラウザ版の出力は 1 サンプル残らず一致する（下の「確認済み」）。

参考にした考え（作曲家イ・ハヌリの Stuff シリーズの出発点として報じられたもの：同じ形が続く団地、
その中で個人の感覚が消されていくこと、同じ物でも置かれる場所で違って感じられること）は、
報道の要約から拾ったもので、作品は聴いていない。題名・手法・響きはまねず、考え方だけを日本の団地に置き換えた。

## 操作

| | |
|---|---|
| **窓（16 戸）** | 押すとその部屋で物が鳴り、今の位置（16 分のマス＋押した瞬間のずれ）に置かれる。同じマスなら写しが重なる。長く押すとその部屋の音が伸びる。右下の灯りで出し入れ（手で入れた／閉めた部屋には「手」「閉」が付き、オペレーターはそれを覆さない）。101 号室は管理人室（拍を守る層）。 |
| キー | `1234`（4 階）`QWER`（3 階）`ASDF`（2 階）`ZXCV`（1 階）。Shift＋キーで出し入れ。Space で音を出す／止める。 |
| **テンポ** | 40〜180 BPM（0 にはならない） |
| **ERASE** | 求める所：個体 ↔ 塊。直接音を変えるのではなく、オペレーターたちが目指す所を動かす。 |
| **食い込み** | 求める所：拍どおり ↔ 先取り。同上。 |
| **META** | オペレーターの生き死にの速さ（何もしない者が尽きるまで：META 0 で約 400 小節、0.35 で約 110 小節、1 で約 10 小節）。 |
| **部屋** | 部屋の響きのくせの強さ（くし形の帰還と、響きの量）。 |
| **遠さ** | 全体の遠さ（こもり・音量・エコー）。各部屋の遠さに足される。 |
| **物** | 回すと候補だけが変わり、押したときに物が替わる。何を選ぶかは物の出どころで変わる：FM の音なら番号（#0001〜#9999）、ファイルなら使う位置、入力からつかんだ音・生成変化なら取る長さ（0.1〜0.75 秒。押すと、その長さでつかみ直す／生成変化する）。 |
| **物の出どころ** | **FM の音**／**ファイル**（WAV・MP3 を選ぶか落とす。波形を押した位置から約 0.75 秒）／**入力**（機器とチャンネルを選び、「そのまま流す」か「つかむ」）。Fireface がつながっていれば最初に自動で選ぶ。 |
| **生成変化** | 押した瞬間に、いま鳴っている団地全体の音（直前の約 0.6 秒、つまみ「物」で長さ）が物になる。押すたびに、その写しを重ねた結果がまた次の物になる。 |
| **足したつまみ** | それぞれ「使う」のチェックで on / off。**生成変化（自動）**：1/2/4/8/16 小節ごとに自動で生成変化。**部屋ごとの周期**：部屋ごとに 12〜20 マスの周期（±0〜4）で、ずれては揃う。**管理人の圧**：管理人の拍ごとに他の部屋を押し下げ、半拍で戻す（管理人がいないと効かない）。**入力で動かす**：入力の大きさ（−50〜−10 dBFS）で、塊らしさ・食い込みの求める所が動く。**刻み**：長い音を 1/2・1/3・1/4・1/6 マスごとに打ち直す（最大 8 回）。 |
| 配置を止める | オペレーターの生き死にと局面を止め、今の並びを保つ（聴くことは続く）。 |
| **エフェクト** | 別の層（下の「エフェクトの層」）。「この層を使う」を切ると、これまでどおりの音に戻る。 |
| 手の動き | 「録る」を入れてつまみを回すと、その動きがループ（1/2/4/8 小節）に録られ、繰り返される。重ね録りできる。 |
| 管理人 | 局面まかせ／いる／いない。 |
| 建て替え | 置き方とオペレーターを作り直す（物はそのまま）。 |

つまみはマウスのドラッグ（縦 6 px ＝ 1 クリック）、ホイール（1 ノッチ ＝ 1 クリック）、矢印キー（1 クリック、Shift で 4）。
どれも機械のエンコーダーと同じ「クリック数」としてコアに渡り、速く回すほど 1 クリックの幅が大きくなる（最大 4 倍）。

画面には、オペレーターの一覧（変え方・部屋・力・前回の効き・何小節おき・年齢）と、各部屋の 1 小節の打点
（グリッドの位置 → 実際に入った位置、音の長さ、押した部屋からの弧）を出している。右下は FM-1 の 240×240 画面で、
同じ C コードが 8 行ずつ描いたものをそのまま表示している。

## 仕組み

### 物（変えない）
2 オペレーター FM の一音。数値の組：基音（92〜420 Hz、音階に乗らない）、比（0.5〜5.196）、変調の深さ（立ち上がりと持続）、
その減衰、振幅の立ち上がり・減衰・持続・放し、自己帰還。物の番号（種）から決まる。
すべての写しは鳴り始めに位相を 0 から始めるので、波形は完全に同じ。ずらして重ねれば、そのずれの分だけ正確にくし形に干渉する。
「伸ばす」は物の中身を変えず、放す時刻を遅らせるだけ（同じ物が長く置かれる）。

### 物の出どころ
バッファは三つに分かれている：入力のリング（1.11 秒）、自分の出力のリング（半分のサンプルレートで 0.74 秒）、物（最大 0.75 秒）。
入力は、つながっている間はいつも記録され続ける。

- **FM の音**：上のとおり。
- **ファイル**：ブラウザが読める形式（WAV・MP3 など）をモノラルにして、選んだ位置から最大 0.75 秒（44.1 kHz で 33,280 サンプル）を物にする。
  端を短く丸め、どの物もだいたい同じ大きさで鳴るように揃える。音の高さ・速さは変えない。部屋の写しは、置かれた長さ（伸び）だけ鳴る。
- **入力・そのまま流す**：写しは **1 拍前の入力** を鳴らす。正確には、写しは「自分のグリッドの位置の 1 拍前」から読み始める。
  だから拍より ¼ マス早く置かれた写しは ¼ マス短い遅れで、遅れた写しは長い遅れで鳴る。時間の交渉で生まれたずれが、
  そのまま入力の遅れの差として聞こえる。重ねた写し（1〜40 ms 間隔）は、入力の音そのものをくし形・フラムで溶かす。
  1 拍がリングに収まらない遅いテンポ（約 64 BPM 未満）では、遅れは 8 分（さらに遅ければ 1 マス）になる。入力そのものはここでは鳴らさない。
- **入力・つかむ**：直前の入力（つまみ「物」で 0.1〜0.75 秒、はじめ 0.6 秒）から、音が鳴り始めた所（最大値の 15% を越えた所の 2 ms 前）を頭にして物にする。
  **流していた写しと同じ大きさのまま**物にするので、つかんだ瞬間に音が下がらない。入力の記録は止まらないので、いつでも何度でもつかみ直せる。
  約 −40 dBFS より小さければつかまない。
- **生成変化**：自分の出力のリングから、直前の音（同じ長さ、最大値の 5% を越えた所から）を物にする。どの物もだいたい同じ大きさに揃える。
  出力は半分のサンプルレート（約 8.8 kHz で切ってから）で持っているので、生成変化を重ねるたびに高域が少しずつ落ちていく。
- つかむ・生成変化のときは、古い物を鳴らしている写しを 4 ms で消してから書き換える（最大 3 ブロック待つ）。

公開ページ（claude.ai）ではマイク・入力の機能が使えないので、入力は手元で開いた `index.html`（localhost か https）でだけ動く。
ファイルと生成変化は公開ページでも使える。

### 足したつまみ（それぞれ on / off）
- **生成変化（自動）**：N 小節ごとに上の生成変化をする（N = 1/2/4/8/16）。
- **部屋ごとの周期**：部屋の並びは 16 マス分のまま、数え方だけ部屋ごとに 16 ＋ (−4〜+4 × つまみ) マスにする。
  たとえば 18 マスの部屋は、小節ごとに 2 マスずつ後ろへずれていき、何小節かで元に戻る。管理人は 16 のまま。
- **管理人の圧**：管理人の打点ごとに、他の部屋の音量をつまみの分（最大 −15 dB 相当）押し下げ、半拍の時定数で戻す。
- **入力で動かす**：小節ごとの入力の大きさ（−50 dBFS で 0、−10 dBFS で 1）から、塊らしさの求める所に最大 ±0.45、食い込みに ±0.26 を足す。
  動かすのは求める所なので、音への効きはオペレーター次第で遅い。
- **刻み**：線をまたいで長く伸びた音を、その長さの間 1/2〜1/6 マスごとに同じ物で打ち直す（最大 8 回）。入力をそのまま流しているときは、打ち直すたびに入力の先へ進む。
- **配置を止める**：オペレーター（生き死にも）と局面を止める。聴くこと、求める所の計算、時間の交渉は続く。

### エフェクトの層（別の層、切れば今までどおり）
部屋ごと（101 の管理人を除く 15 部屋）に、エフェクトごとの値（0〜1、0 はその部屋には掛けない）を持つ。
その部屋の写し一つ一つ、つまり時間の画面の色の棒線一本一本に、鳴り始めた時点の値が掛かる。

| エフェクト | 値の意味 | 中身 |
|---|---|---|
| グリッチ | 0〜100% | 1〜13 サンプルごとに値を保持（粗くする）し、30 ms ごとにその確率で読む位置（FM では位相）を飛ばす |
| ディレイ | 0.5・0.75・1・1.5・2・3 マス | 同じ写しを、その間隔で 3 回、0.55 倍ずつ小さくして置き足す（遅れ線は使わない） |
| ピッチ | −12・−7・−5・−3・+3・+5・+7・+12 半音 | 読む速さ（FM では周波数）を変える |
| スタッター | 1/16・1/32・1/64・1/128 | 写しの最初の一切れを、その長さで繰り返す |
| 逆再生 | 音の長さの 30〜100% | その長さを後ろから読む。FM の音では、だんだん大きくなって切れる形にする |

- 各エフェクトにチェック（on / off）とサイコロがある。サイコロは、チェックしたエフェクトについて、部屋ごとに「掛けるか（55%）」と値（0.1〜1）を振る。
  チェックを入れたとき、まだどの部屋にも値がなければ一度振る。「振り続ける」で 1〜16 小節ごとに自動で振る。
- 表のセルは左右にドラッグで値、ダブルクリックで 0。
- 時間の画面では、ピッチは半音数、スタッターは区切りの線、グリッチは切れ目、逆再生はだんだん濃くなる棒、ディレイは後ろに薄い棒で示す。
- サイコロは団地の他の部分と別の乱数を使う。だから**層を切っているときは、チェックや値やサイコロをいじっても、音は今までと 1 サンプルも変わらない**（試験で確認）。

公開ページ（claude.ai）ではマイク・入力の機能が使えないので、入力は手元で開いた `index.html`（localhost か https）でだけ動く。
ファイルは公開ページでも読める。

### 置き場所（変わるのはこれだけ）
- **時間**：16 分のマス、跳ね（奇数マスを最大 0.44 マス遅らせる）、手で置いたときのずれ、下の「交渉」。
- **左右**：はじめは窓の位置（列）。
- **遠さ**：2 次のこもり（16 kHz → 約 500 Hz）、音量（最大 −8 dB）、エコーへの送り。上の階ほどはじめは少し遠い。
- **部屋**：2DK の 6 部屋。和室（柔らかい）、洋室、台所（硬く明るい）、浴室（強く鳴る）、押入れ（死んだ響き）、階段室（長い）。
  それぞれ、くし形 2 本（1.2〜21.7 ms）と短い反射、帰還量・こもりが違う。
- **隣**：同じ物がどれだけ近くに重なるか。写しの間隔 5 ms 未満はくし形（音色が溶ける）、5〜40 ms はフラム。

### 時間の作り：関係から出てくるずれ
各小節は始まる 2 マス前に計画される。写しを時間順に一つずつ置いていく：

1. **返す**：前に借りた時間（早く入った分）の一部を、遅れることで返す（`返す率 × 借り × 0.6`）。
2. **押される**：別の部屋の音がまだ鳴っていて、しかもそれが 8 分の線をまたいで伸びているなら、その重なりが「押し」になる。
   隣の部屋は 1、二つ隣は 0.6、それより遠くは 0.35 の重み。前のめりの部屋（lean > 0）は `lean × 押し × 0.85` マス早く入り、
   譲る部屋（lean < 0）はその分待つ。
3. **自分の伸び**：自分の音が次の 8 分の線を越えて伸びるなら、その半分の強さで前へ引かれる（ラグのタイ）。
4. **早く入った分だけ長くなる**（終わりの位置は変わらない）。すると今度はその音が線をまたぎ、次の部屋を押す ── 連鎖。
5. 借りは ±1 マス、ずれは −1.2〜+0.9 マスまで。小節の線ごとに借りの 6 割だけが残る（4 割は小節頭で清算される）。
   これが無いと、前のめりの部屋では借りが上限に張り付き、「返す」がずっと続く遅れに変わってしまった。

乱数の揺らしは一切ない。どの打点にも「どの部屋に押されたか」が記録され、画面に弧で出る。
101 号室（管理人）は四分音符で拍を守り、ずれない、伸びない、押さない。いるかどうかは局面が決める
（個体 95%、行列 90%、塊 50%、空き部屋 60%）。手で「いる／いない」に固定もできる。
※線を「拍（4 分）」ではなく「8 分」にしたのは試作の途中での判断（下の「批判」）。

### 毎小節、聴く
鳴った音そのものと、実際に鳴り始めた時刻から：

- **輪郭**：出力の包絡の谷の深さ（10% 点と 90% 点の比）と、各打点の立ち上がりの鋭さ（直前の音量からどれだけ上がったか）。
- **密度**：同時に鳴っている写しの数（対数）。
- **フラム／重なり**：打点どうしの間隔が 5〜40 ms ／ 5 ms 未満だった割合。
- **干渉**：写しを足した音のエネルギーと、写し一つずつのエネルギーの和の比（くし形・打ち消し）。
- **中央寄り**：左右の相関。
- **先に入った／遅れた**：管理人の格子に対して、実際に鳴った時刻がどれだけ前・後ろか。

```
塊らしさ   = 0.40×(1−輪郭) + 0.25×密度 + 0.15×(フラム + 0.5×重なり) + 0.12×干渉 + 0.08×中央寄り
食い込み度 = (先に入った + 0.15×遅れた) / 0.25     （どちらも 0〜1 に収める）
```

### オペレーター（変化の変化）
8 つ。それぞれ一つの変え方を持つ：跳ねさせる、伸ばす、先取りさせる、譲らせる、貸しを返させる、部屋を替える、遠ざける、
重ねる、間引く、左右へ動かす。各自が目標の値（遺伝子）と、何小節おきに動くか（2〜12）を持つ。

- 一度に動くのは一つだけ。動いたら少なくとも 3 小節（求める所に近いときは 4 小節）は誰も動かない。その変化は繰り返しの中で聞こえる。
- 動くのは、順番が来ていて、いちばん力のあるもの。担当の部屋にもう変えることがなければ、廊下を隣の部屋へ歩いてそこで変える。
- 動いた 3 小節後、「動く前の 2 小節」と「動いた後の 2 小節」で、求める所までの距離（2 軸の差の和）がどれだけ縮んだかを測り、
  それが効き（−1〜+1）になる。力は効き × 0.8 だけ増減する。毎小節、`0.0025 × 40^META` ずつ力が減る。
- 力が尽きたものは死に、効きを実際に示したもののうち、いちばん強いものの少し違う子が生まれる（遺伝子 ±、たまに変え方や部屋も変わる）。
  誰も効きを示していなければ、集団にない変え方の新入りが来る。同じ変え方は 3 つまで。古い効きの記憶は毎小節 0.93 倍に薄れる。

### 局面
個体・行列・塊・空き部屋。求める所を傾ける（個体：塊らしさ −0.24、行列：食い込み +0.24、塊：塊らしさ +0.28、
空き部屋：塊らしさ −0.32・食い込み −0.2）。空き部屋では、ある部屋の種類（例：浴室）の住人がその局面の間いなくなる
（手で入れた部屋は残る。鳴る部屋が 2 つ未満になるなら空けない）。
長さはパレート分布（α = 1.2、8〜400 小節）：中央値 14 小節、たまに数百小節。

### 消える（ERASE）
ERASE を上げると、重ねる・伸ばす・遠ざける・中央へ寄せる変え方が効くようになって生き残り、写しが増え、間隔が詰まり、
輪郭が溶けて塊になる。下げると間引く・縮める・近づける変え方が生き残り、一つずつに戻る。つまみは願いを置くだけで、
実際に変えるのはオペレーターたち。

### 手の動き
つまみの動きを、小節あたり 64 区切りでループに録る（「物」以外のすべてのつまみ。足したつまみも）。
「止まってから動いた」は手全体の静止（0.35 秒、どのつまみも動いていない）で判定する。一つのジェスチャーの間に触れたつまみは
すべて録られ続け、別のつまみに触れただけでは新しいジェスチャーにならない。録っていない間に回したつまみは、手が止まると録った動きに戻る。

## 確認済み（数値で確かめたこと）

（数値は `build/sim test` の出力。44.1 kHz、この開発機の x86-64 で測った。）

- **メモリ**：作業用 `dn_state` 56.1 KB（予算 96 KB）、大きなバッファ `dn_big` 335.2 KB（予算 336 KB）。
  入力・出力・物の三つのバッファを入れるため、エコーを 16 bit・0.37 秒にし、部屋の遅れを 48 kHz で要る長さに詰めた。
- **単精度のみ**：Cortex-M4F（単精度 FPU のみ）向けに組んで、倍精度の補助関数・倍精度命令・libm 呼び出しが一つもない。
  外部に要るのは `memcpy` だけ。コードは約 43 KB（コア）＋ 18 KB（画面）。
- **同じコア**：同じ種・同じ操作で 60 秒（FM → 入力をそのまま → つかむ → 読み込んだ音 → 部屋ごとの周期 → 生成変化 → 刻み →
  管理人の圧 → エフェクト 5 種すべて・毎小節サイコロ、の順に切り替え、入力も同じものを与えて）、
  ネイティブ版と WebAssembly 版の出力が 2,645,888 サンプルすべて一致。
  JS 変換の予備も WebAssembly 版と全サンプル一致。
- **因果**：A の伸びた音が線をまたぐと B が −0.213 マス（計算どおり）早く入り、原因として A が記録される。A を消すと B は拍どおりに戻る。
  B が譲ると +0.213 マス遅れる。A → B → C の連鎖：A を消すと二つ先の C のずれ（−0.298）が消える。
- **貸し借り**：−0.157 マス早く入った B の次の打点が +0.124 マス遅れて返す。返す率 0 なら返さない。
- **局面の長さ**：2 万回で中央値 14、平均 29.5、90% 点 55、99% 点 353、最大 400 小節。同じ局面が続けて選ばれることはない。
- **閉ループ（6 種の平均）**：
  ERASE を 0.1 → 0.9 にすると、聴いた塊らしさは 0.25 → 0.59（オペレーターを止めると 0.35 のまま動かない）。
  0.1 に戻して 200 小節後も 0.48（戻り切らない：試験では OPEN）。
  食い込みを 0.05 → 0.95 にすると 0.12 → 0.39、戻すと 0.35（ほとんど戻らない：OPEN）。
- **一度に一つ**：2400 小節で 687 回の変化。間隔は最短 3 小節、平均 3.5 小節。二つ同時に動くことはない。
- **生き死に**：2400 小節で 292 回死に、292 回生まれた。
- **平均化しない**：32 小節ごとの塊らしさの平均が 0.15〜0.73 に散らばる（標準偏差 0.177）。局面は 4 つとも出る。
- **音量の余裕**：既定のまま 10 分で最大 0.597（−4.5 dBFS）、実効値 −23.2 dBFS。リミッターが 1 dB 以上効いた時間は 0 秒。
  15 部屋 × 4 打点 × 写し 2、長い音の混んだ状態でも最大 0.63（−4.0 dBFS）で割れない。
- **非正規化数**：手で全部屋を閉めて 2 分、状態に非正規化数が一つもない。無音の処理は鳴っているときより速い（止まりの罠がない）。
- **止まる罠がない**：テンポは 40 BPM で止まる。「個体」を求めて生き死にを最速にした 600 小節でも、鳴る部屋が 2 未満にならない。
  手で全部屋を閉めたときだけ無音になり、画面にそう出る（オペレーターも勝手に住人を入れない）。
- **手の動き**：録った ERASE の掃引がループの次の周回で同じ値の範囲（0.38〜1.00）で戻る。ジェスチャー中に別のつまみに触れても、
  新しいジェスチャーは始まらない。
- **同じ種なら同じ音**：2 回の実行がビット単位で一致。
- **物の出どころ**：読み込んだ 0.4 秒の音が物になり、FM と同じように置かれて鳴る（最大 0.45）。入力は物のバッファに触れない。
  入力をそのまま流すと、グリッドどおりの写しは入力をちょうど 1 拍（88 BPM で 30,068 サンプル）遅れで鳴らし、
  ¼ マス早く置いた写しはちょうど ¼ マス（1,879 サンプル）短い遅れで鳴らす（どちらも ±0 サンプル）。
  無音はつかまず、0.3 秒の音＋0.1 秒の無音をつかむと、音の頭からの 0.397 秒が物になる。
- **つかんでも下がらない**：同じ入力で、そのまま流した写しは −20.6 dBFS、つかんだ後も −20.6 dBFS（差 +0.1 dB）。
  つかんだ音を鳴らしている最中に、もう一度つかめる。
- **生成変化**：押すと、いま鳴っている音（0.60 秒）がすぐ物になり、その後も鳴り続ける（最大 0.31）。自動を毎小節にすると 6 小節で 5 代。
- **足したつまみ**：部屋ごとの周期 18 マスの部屋は、鳴る位置が小節ごとに 2 → 4 → 6 → … → 14 とずれ、次の小節には鳴らない（そして戻る）。
  管理人の圧を最大にすると全体の実効値が −1.1 dB。刻み 1/4 マスで長い 1 音が 8 回の打ち直しになる。
  入力で動かす：小さな入力では求める塊らしさ 0.00、大きな入力（−6 dBFS）では 0.48。配置を止めると 100 小節の間、何も変わらない。
- **エフェクトの層**：
  - **層を切った音は今までどおり**：すべてにチェックを入れ、値を入れ、毎小節サイコロを振っても、20 秒間の音が 1 サンプルも変わらない。
  - **ピッチ** +12 で周波数が 1.99 倍。
  - **逆再生**：打った音の前・後ろ 3 分の 1 の大きさが、元は 0.127 / 0.013、逆再生で 0.001 / 0.055（だんだん大きくなる）。
  - **スタッター**：次の一切れとの相関が 0.07 → 1.00。
  - **ディレイ**：1 つの写しが 4 つになる。
  - **グリッチ**：音が変わり、値は有限のまま。
  - **サイコロ**：チェックしたエフェクトだけが変わり、値は 0 か 0.1〜1、管理人には掛からない。2 小節ごとなら 10 小節で 5 回振る。
  - 5 種すべてを毎小節振りながら 60 秒鳴らしても、割れず（最大 0.38）、非正規化数も出ない（132 倍速）。
- **画面**：帯ごとに描いた画面と一度に描いた画面が一致。1 フレーム 31 µs（この開発機）。
- **ブラウザ**（ヘッドレス Chromium、HTTP 経由）：AudioWorklet で動き、小節が進み、画面が届く。窓・ホイール・Shift＋キーが効く。
  コンソールのエラーなし。幅 390 px で横にはみ出さない。WebAssembly を取り除くと JS 変換＋ScriptProcessor で鳴る。
  WAV を選ぶと物になり、波形の後ろの方を押すとそこからに替わる。入力は Chromium の擬似入力機器（試験音）で：一覧が出て、
  そのまま流すと 1 拍（682 ms）遅れで鳴り、つかむと物になる。生成変化のボタンで物が 1 代目になり、つまみ「物」を回すと長さ（0.50 秒）が、
  押すと 2 代目になる。足したつまみの「使う」と「配置を止める」、エフェクトの層・チェック・サイコロ・セルのドラッグ（404 のピッチを右端で +12）・
  毎小節の自動サイコロがそれぞれ効く。
- **速さ**（この開発機、1 コア）：ネイティブ 約 140〜220 倍速（混み具合で変わる）、WebAssembly（node）約 80 倍速、JS 変換 約 2.4 倍速。

## 批判（弱点と、解けていないこと）

（入力・ファイルについて）

- **「そのまま流す」は「物は変えない」を破っている。** 写しはどれも同じ入力の流れだが、それぞれが別の瞬間を鳴らすので、
  中身は写しごとに違う。物を固定したいなら「つかむ」を使う。どちらが考えに沿うかは、聴いて決めることだと思う。
- **物は最大 0.75 秒（前は 1.47 秒）。** 入力・出力・物を別々に持ち、しかも機械の 336 KB の枠に収めるため。長いフレーズや声の一文は入らない。
  ブラウザ版だけ長くすることもできるが、同じコアという約束を崩すのでしていない。
- **生成変化は世代ごとにこもる。** 出力を半分のサンプルレートで持っているため。気に入る場合もあるが、選べない。
- **遅れは 1 拍で固定。** 入力を弾きながら聴くと、自分の音が 1 拍後に部屋ごとにずれて返ってくる。この長さを選べるようにはしていない。
- **入力そのものは鳴らさない、回り込みも止めない。** スピーカーとマイクだと、写しがまた入力に入って 1 拍ごとに積み重なる（リミッターで割れはしない）。
- **つかむ位置は機械的。** 「最大値の 15%（生成変化は 5%）を越えた所」を頭にするだけで、拍や音の切れ目は見ていない。

（足したつまみ・エフェクトの層について）

- **エフェクトの層は、元の考えの外にある。** ピッチと逆再生は物そのものを変え、サイコロは乱数でずらす。どちらも最初の注文で避けたことなので、
  別の層にして、切れば元どおり（1 サンプルも変わらない）にした。
- **管理人の圧は控えめ。** 全体の実効値で −1.1 dB。押し下げと戻りの形は耳で合わせていない。
- **入力で動かすのは求める所だけ。** 弾く大きさがすぐ音に出るわけではなく、オペレーターを通るので遅い。
- **グリッチの飛びは入りだけ丸めている。** 飛ぶ直前は切れるので、小さなクリックが出る（グリッチとしては意図に近いが、選べない）。
- **刻み・ディレイは打点を大きく増やす。** 混んだ状態では 1 小節 200 打点・予約 256 件の上限に当たり、超えた分は黙って落ちる。

（全体について）

1. **つまみへの応えが遅く、届き切らない。** ERASE や食い込みを大きく回しても、200 小節（88 BPM で約 9 分）で
   動くのは求めた差のうち、ERASE で約 4 割、食い込みで約 2 割。方向は確かに合う（オペレーターを止めると全く動かない）が、
   弾き手には「聞こえたのかどうか」が分かりにくい。「とても遅い変化」という狙いと、楽器としての手応えが噛み合っていない。
2. **効きの測り方が粗い。** 「動く前の 2 小節」と「後の 2 小節」の比較なので、その間の手の操作、局面の切り替わり、
   手の動きのループもそのオペレーターの手柄（または失敗）になる。複数の段階が要る変化（伸ばしてから先取りさせる）は、
   一つずつの動きでは効きが出にくい。
3. **戻りが遅い（未解決）。** 一度「塊」や「食い込み」へ寄った後、つまみを戻しても 200 小節では半分も戻らない
   （試験では OPEN と表示）。上がるときは「重ねる」「伸ばす」「先取りさせる」のような一方向の変え方が効くが、
   戻るには多くの部屋を一つずつ戻す必要があり、その変え方を持つ者が集団に育つまで時間がかかる。
   借りの扱いも 7 通り試した（返し終わるまで借りられない、半分だけ借りになる、小節の線で清算、など）。
   どれも戻りは良くならず、厳しい貸し借りほど食い込み自体が作れなくなった。
4. **最初の版は食い込みを全く作れなかった。** 押しが「隣の部屋の、拍をまたぐ音」の偶然に頼っていたため。
   そこで (a) 線を 4 分から 8 分にし、(b) 遠い部屋も弱く押すようにし、(c) 自分の伸びで前へ引かれる規則を足し、
   (d) オペレーターが廊下を歩くようにした。いずれも試験を通すための調整で、特に (c) は「関係だけから時間ができる」という考えを弱めている
   （自分の長さが原因の先取りは、隣との関係ではない）。
5. **聴く物差しは手で決めた重み付け。** 9 つの作った場面で範囲を合わせただけで、耳で合わせていない。フラムや干渉はすぐ 1 に張り付く。
   「うなり」は、音高が一つなので本来は生じず、測っているのはエネルギー比による干渉だけ。
6. **局面が短すぎて傾きが聞こえにくい。** 中央値 14 小節の局面は、オペレーターが応える前に終わることが多い。
   局面の違いは主に管理人の有無と空き部屋で聞こえ、求める所の傾きとしてはほとんど効いていないはず。
7. **一つの 16 マスの小節が基準。** 部屋ごとの周期（足したつまみ）を使えば部屋ごとにずれていくが、交渉と聴くことは 16 マスの小節ごとのまま。
8. **手で置いた写しは次の周回から。** 押した音はすぐ鳴るが、置かれた写しが鳴るのは最大 2 小節後。
9. **混んだときの声の取り合い。** 32 声を超えると古い音が 1.5 ms で消される。塊の厚みはこの上限で頭打ちになる。
10. **JS 変換の予備は重い。** WebAssembly の約 35 倍の負荷（机上の PC で 1 コアの約 4 割）。遅い機械では途切れるはず。
11. **画面は描画側と音声側で鍵をかけずに状態を読む。** 1 フレーム古い値が混ざることは許しているが、FM-1 の実行環境で問題ないかは未確認。
