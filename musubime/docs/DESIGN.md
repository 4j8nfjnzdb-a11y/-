# 結び目（musubime）の設計

FM-1 のための 6 つの別々のファームウェアです。方法の違いがそのまま分かれ目になるようにしています。どれも、シンプルな位置（ほぼ一本のサイン波）から始まり、数学の規則と手の動きによって、非線形に複雑なほうへ動いていきます。

この文書では、何がどこから来た考えで、何が未確認かを分けて書きます。最後に、この設計への批判と穴を置きます。

## 前提: 思考と道具は切り離せない

peeq の投稿（2026/11/16）は、Mark Fell の論文 *Works in Sound and Pattern Synthesis*（University of Surrey）を引いています。Phuture と TB-303 の出会いのような、道具のアフォーダンスへの没入的な応答は、「理論的分析」よりも根源的な関係を道具と結ぶ、という一節です。peeq はこれに対して、二つの問いを立てています。

- 思考を身体的・物質的な実践から切り離せるものとして扱った時点で、デカルト的なパラダイムを保持していないか。
- 実践と思考は相互に浸透していて、切り離せないのではないか。

musubime はこれを前提として受け取り、次のように設計に落としました。

- **数学は、手の上に乗る「理論の層」にしない。** 規則（ロジスティック写像、無理数の回転、1/f、ホメオスタシス）は、道具の性格（抵抗、粘り、勢い、癖）として手に返ってきます。手の動き（速さ、往復、静止、動き出し）は、値ではなく規則の側を変えます。例: ヒステリシスの幅、変異の向き、配線、帯の幅、我慢の長さ。
- **画面の数値は、分析の結果ではなく、楽器のフィードバックの一部。** TB-303 のつまみの位置が手と耳の間にあるのと同じ位置に置いています。ただし、数値を見つめることが聴くことを奪う危険はあります（「批判と穴」）。
- **わからないものはわからないまま。** 規則は、予測できないが、聞き続けると何かの規則がありそうだと感じられる程度に設計しています（「漠然としたルールの認知」）。どれも乱数ノブの並びではありません。

## 落とし穴をどう塞いだか

| 落とし穴（依頼文） | ここでの扱い |
| --- | --- |
| 既製の音色をありがちな音程で鳴らす | 音程を選ぶ仕組みはどこにもない。音域（REG）は連続値。音の間の関係は無理数比か数十セントのずれで、音階の度数ではない。キック・スネア・ハット・シンセは「同じ 12 個の数の空間の中の出発点」で、プリセットではない（ただし「批判と穴」の 4 を参照） |
| 音程の並びだけを決めるシーケンサー | 変化（HENKA）のロックは、音の中身の数（比率、インデックス、フィードバック、ノイズ、減衰、XMOD、ビット）に当たる。線（SEN）の変化は 8 つの次元すべてに及ぶ |
| 乱数ノブを並べるだけ | 乱数は、写像・勢い・帯・条件の中で使うだけ。手で回すのは規則の側 |
| 完全なカオス（統計的に一定） | ファイゲンバウム点（カオスの縁）、1/f、恒常性と構造の跳躍（断続平衡）、戻らない変化。どれも「平均すると同じ」になりにくい形を選んでいる |
| 全部入りのプリセット巡り | 6 つは別々のファームウェア。切り替えは入れ直しで、前の状態は残らない。重ねるのは明示的な操作のときだけ（崩しの VOICE ページ、変化の XMOD） |
| 理論家の考えを音程の選び方にだけ当てる | 近藤は線の音の「次元」と変化の規則に、フェルドマンは反復のずれと音色・音量の揺らぎに、佐藤は時間の種類と切り替えに当てた。どれも音程の選び方には当てていない |

## 6 つのプロジェクト

### 1. 崩し KUZUSHI（UNDERFLOW の発展）

- **方法**: 音の数値を直接崩す段（オーバーフロー、サンプルレート、ビット深度、浮動小数点、ビット反転、エンディアン、吸収、ジッター、ブロック）。崩した出力を FM キャリアの位相へ戻す（LOOP）。
- **数学**: 量子化器・桁あふれ・アンダーフローを帰還ループの中に置くと、区分的に一定な写像の反復になり、周期が長く変わりやすい軌道（モードロック）が出る。ABSORB `(x + 2^k) − 2^k` は、浮動小数点の binade のせいで、正と負で刻みが 2 倍違う量子化になる（固定小数点にはない非対称）。EXP を減らすと、小さな値が 0 に落ちる（アンダーフロー）。
- **UNDERFLOW から変えた点**: FM-1 のために軽くした（STFT のビットレート、sinc 再構成、1 bit シグマデルタは入れていない）。代わりに、LOOP、ヒステリシス量子化、ABSORB、身体による配線を加えた。
- **身体**: 往復するとヒステリシスが広がる。速いとクロックが揺れる。2 秒以上の静止の後に動くと段の順番が回り、5 秒以上ならその前に一瞬切れる（メルツバウ的な唐突な切断を、静止の長さに結んだ）。
- **操作の割り当て（実機で触った後に変えた）**: 6 ページをボタンに置いた（ARP SOURCE、ENV RATE、SEQ FLOAT、LFO BITS、SEL TIME、GLO VOICE）。ページを潜らず一押しで開ける。SELECT は DRIVE（桁あふれへ入れる量）。FX を押している間は凍結（SR = 0 と同じ）、SAVE は今の崩し方を取っておき、長押しで戻る。OCT− / OCT+ は元の音のオクターブ。使えるボタンは薄く光り、今のページは明るく光る。

### 2. 変化 HENKA（Digitakt 的な「変化し続ける」生成）

- **方法**: パラメーターロック、条件トリガー（確率、A:B、PRE、NEI、1ST、FILL と否定）、トラックごとの長さ（ポリメーター 16 / 12 / 7 / 5）、LFO。条件の種類は Digitakt のもの（Elektron のマニュアルの名前に合わせた）。
- **声**: 4 トラック × FM の声（`fmvox.h`）。キック（ピッチの指数的な落下と、すぐ減衰するインデックス）、スネア・ハット（強いフィードバックで周期を失ったサイン波を「ノイズ」として使う）、シンセ（2 オペレーター＋フィードバック）。4 種類は同じ 12 個の数の点にすぎない。XMOD で上のトラックが下の声を FM 変調する。トラックは抜き差しできる。
- **変化し続ける仕組み**: ループの終わりごとに確率 MUT で一か所だけ変わり、戻らない。ロックの値は勢い（momentum）を持って一方向に進み、壁で折り返す。キック 1 つから始まって、他のトラックが少しずつ埋まる。
- **時間が変わる（TIME）**: トラックごとにテンポに対する速さ RATE（1/4、1/3、1/2、2/3、3/4、1、4/3、3/2、2、3、4）を持つ。3/4 と 1 が並ぶのは、拍の数のずれ（ポリメーター）ではなく時間と時間のずれ。TIME（ALGO）を上げると、ステップのずらし（後ろへ 1/16 ステップ単位、最大 10/16）が勢いを持って同じ向きへ育ち（見つかるグルーヴ。ティポグラフィカの「訛り」を意識した）、トラックの長さや RATE が隣へ動き、テンポが 1/f でゆっくり息をする（±TIME×7%）。どれも戻らない。
- **密度の釣り合い**: 実機で「ハイハットが鳴りっぱなし、全部が一斉に鳴って直せない」と言われた後に作り直した。変異はトラックの DENSITY（K3）を目標にして、少なければ足し、多ければ減らし、ちょうどならロックを動かす。だから変わり続けても埋まり切らない。伸ばす音は 4 ステップでフェードする。
- **つまみはすぐ効く**: SELECT トラック、ALGO TIME、PRESET RATE、K1 TONE、K2 DECAY、K3 DENSITY、K4 MUT。白鍵（ステップ）を押さえている間だけ、つまみがそのステップのロック行き先・ロック値・条件・ずらし・長さになる。ボタンは全部に役割がある（トラックの出し入れ、間引き / 空に、取っておく / 戻る、変化を止める、FILL、テンポ）。
- **GEN（生成、FX）**: 実機で「シンセが一種類でほとんど変わらない」「生成の感じが弱い」と言われて足した。ステップに「印」が付く: ラチェット、倍音列の音程、和音（あと 2 声）、エコー送り、スタッター（直前のミックスをループ）、クラッシュ（サンプル保持とビット落とし）、スイープ（音の中でインデックスが上がる／下がる）。どれを、どのトラックに、どれだけの割合で付けるかは局面（PULSE / SONG / BREAK / DRIFT / VOID）が決める。局面の長さはパレート分布（α = 1.2: たいてい 1〜3 小節、ときどき何十小節。平均に意味がない）、次の局面はファイゲンバウム点のロジスティック写像を左右で読んだ周期倍分岐列（非周期で自己相似）で選ぶ。割合より多い印は消えるので、FX 長押しのバーストで付いた印は間引かれていく（平均ではなく対比）。局面が変わるたびに倍音列の一つが動き、シンセのトラックは別の音色の場所へ少しずつ寄っていく（着かない）。音程は倍音 8・9・11・12・13・7・15 をオクターブに畳んだ集合からで、音階や三和音の定型は使わない。
- **身体**: 往復で全トラックの勢いが反転する。手全体の静止の後の動き出しで、次のループが FILL になる。手の運動量が MUT と GEN の速さに足される。

### 3. 線 SEN（近藤譲「線の音楽」）

- **方法**: 一音ずつ、上下関係なしに並ぶ線。一周ごとに一か所だけ変わり（一つの音の一つの次元）、元に戻らない。
- **数学**: 各音の 8 つの次元はトーラスの上の座標で、変化はそれぞれ違う無理数（黄金比、√2−1、√3−1、…）倍の一歩。だから線全体は、同じ状態に二度と戻らない（個々の値が昔の値の近くを通ることはある）。どこを変えるかは、ファイゲンバウム点（r = 3.5699456…）のロジスティック写像で決める。周期でも乱数でもなく、カントール集合上を自己相似に偏って動く。次元は連続して同じにならない歩みで選ぶ。3 音から始まり、分裂しながら LENGTH まで伸びる。
- **身体**: 運動量で変化が大きくなる。往復で向きが反転する。静止が長いほど変化は小さくなり、反復に近づく。動き出すと、線の遠くの音が一つ変わる。鍵は「この音」を指さし、押し込みの強さが変化の大きさになる。

### 4. フェルドマン FELDMAN（Crippled Symmetry）

- **方法**: 3 層の短いパターンが、層ごとに少し違う単位時間（ASYM、無理数のずれ）で反復し、ずれていく。反復ごとに 1/f の揺らぎ（アブラッシュ: 絨毯の染めのロットごとの色むら）で色と音量が少し動く。ときどき一つの音が 1 単位伸び縮みして戻らない（crippling）。小さく、静か（RMS で約 -19 dBFS）。
- **音高**: 層ごとに REG の無理数倍（1, √φ, φ）。隣り合う音は数十セント離れていて、聞こえるのは音程よりうなりと色。
- **身体**: 逆に応答する。手が激しいほど静かになる。静止で揺らぎは収まるが、crippling は残る。

### 5. PMVRS（佐藤允彦『完全即興』）

- **方法**: P パルス（アクセントも小節もない）、M 長短（フィボナッチ語の並び: 周期でも乱数でもない）、V 速度感（間隔が指数的に縮む・伸び、限界で折り返す）、R 呼吸（押し込みがそのまま息。押していなければ、吸うより吐くが長い 1/f の息）、S 無音。これらを混ぜずに切り替える（1.5 ms はクリック防止だけ）。各モードは自分の音色を持ち、オンの間だけ複雑になる。S の間も、すべてのモードは少しずつ育つ。
- **意識の切り替え**: 5 つの鍵、SELECT、または身体（静止の後につまみを動かすと、いちばん長く離れていたモードへ）。どのモードの後にどれが来るべきかという理論は置いていない。

### 6. 適応 TEKIOU（Adapt / Di Scipio / Ashby）

- **方法**: 4 つの FM オペレーターと 4×4 の変調行列。空（純音）から始まる。自分の出力の明るさ（ゼロ交差、対数）と、その揺れを聴く。
  1. 恒常性（連続的）: インデックスの全体のゲインが、明るさを目標へ寄せる（HOMEO がマイナスなら遠ざける: 暴走）。
  2. 超安定性（Ashby、段階的）: 明るさが帯の外にいる時間が PATIENCE を超えるか、揺れがなさすぎると（退屈）、構造が一歩変わる。エッジの追加・削除・反転、比率の変更、出力の付け替え。地味すぎれば足し、過剰なら削る。
  - 目標は年齢とともに上がり、複雑へ成熟する。
- **入力が構成を変える**: 手で変えるのは値ではなく、目標、帯の幅、我慢、恒常性の符号、聴く時定数。REWIRE を回すと、その場で構造が一歩変わる。外からの音（プレビューのファイル・マイク）は、出力と一緒に聴かれ、オペレーター 1 を変調する（Commuta 的な相互適応の一番小さい形）。
- **身体**: 激しいと帯が狭くなる（神経質に）。静止で帯が広がり、我慢も長くなる。往復で恒常性の符号が反転する。動き出しで驚いて一歩変わる。
- 実際の動き: 放っておくと約 20 秒は純音のまま、そこから一歩ずつ構造が増え、平らな時期と跳躍が交互に来る（断続平衡）。

### 7. 流転 RUTEN（変化の変化）

- **依頼**: 「変化を変化していく」。suzukiski のインタビュー（ハウスに「まんま」ではなく斜に構えて向き合い、結局ヘンテコになる。何かに寄せない姿勢が「誠実」と言われた）、中村としまるのノーインプット、Autechre の系、KORG DS-10（DS の小さな道具の設計から、設計を超えた挙動が出てくる）。「四つ打ちの瞬間があってもいい、それ以外が動く、反復と差異」。参考にしつつ、参考にしない。
- **方法**: 変化（HENKA）のパターン機械はそのまま使い、パターンを変えるものを、決まった規則から**オペレーターの集団**に替えた。オペレーターは「一つの変え方 × 一つのトラック × 何小節おきか」。16 種類（足す・引く、ずらす、ロックを歩かせる、速さ、長さ、ノッジ、回す、条件、床へ、床から、和音、ベンド、効果、音色、引っぱり合い、拍子）。
- **二次の変化**: 系は毎小節、自分の音を聴く（各トラックが前の小節を何割繰り返したか: ステップの集合の Jaccard 係数の平均）。求めるもの（ORDER に局面の傾きを足したもの）との差が「必要」。各種類は反復か差異へ傾いている（床へ +1、床から −1、速さ −0.8、和音 −0.05 …）ので、必要に合った向きのオペレーターが力を得て、合わないものが失う。力が尽きたもの（META が速さ）は死に、いちばん強いものの子が生まれる（4 割で種類が変わり、そのときは必要に合う種類が選ばれやすい。同じトラックに同じ種類が重なると互いに力を削る）。アシュビーの超安定、ディ・シピオの自分を聴く系、人工生命の集団を、小さく組み合わせた。
- **床**: キックが 1・2・3・4、クラップが 2 と 4、オープンハットがその間、裏のコードスタブ。FLOOR はここへ寄せ（速さを 1 に、長さを 16 に、拍子を 4/4 に戻してから、外れたステップを一つ消すか、欠けたステップを一つ足す）、SCATTER は散らす。ここから始まり、ここへ落ちたり抜け出したりする。
- **和音**: 4 声。純正律のディープハウスの響き（1 6/5 9/5 9/4 のマイナー 9th 五度抜き、1 5/4 15/8 9/4、1 4/3 16/9 9/4、倍音の 7th 1 5/4 7/4 9/4）が出発点。CHORD オペレーターは、別の響きへ戻すか、根音を 4 度・5 度・3 度・全音動かすか、CHORD つまみの分だけ一つの声や根音を小さな奇数比（21/20、15/14、36/35、8/7、11/10、7/6、11/8）でずらす。BEND は次の数回の和音を、鳴りながら下へ曲げる。
- **FBACK（ノーインプット）**: 自分の出力と、エコーの中のミックスの記憶で位相変調されるサイン波。恒常性が「ざらつき」を狙いの値へ寄せるので、音とノイズの境目を探し続ける。狙い・高さ・エコーを読む位置は、開くたびに変わる。数秒ずつ開いて閉じる。
- **実際の動き（10 分の記録）**: 最初は床のオペレーターが二つ。局面が DRIFT に変わると床が死に、長さと引っぱり合いのオペレーターが増え、その後 TOKEN・BEND・CHORD が現れ、古い顔ぶれは赤くなって入れ替わった。繰り返しの度合い R は 0.38〜0.96 を行き来した。

## 共通のしくみ

- **音源（EDIT を押している間）**: FM の 28 種類の音色のバンクと、4 つのスロット。どれも同じ 15 個の数（音高、ピッチの落ち方、比率、インデックスとその減衰、フィードバック、FM ノイズ、金属感、減衰、XMOD、ビット、アタック、第 2 オペレーターの比率とフィードバック）の空間の中の点で、プリセットではない。スロット 2〜4 を空にすれば 1 つの音源で全部が鳴り、スロット 1 も空なら各プロジェクト自前の FM に戻る。フラッシュに置くのは 28 × 15 個の数（約 1.7 KB）だけ。
- **耳を守る**（`src/shell.c`）: DC カット、急な跳ね上がりのガード（直近 5 ms と 1.5 s の電力比が 18 dB を超えたら最大 -9 dB、0.3 s で戻す）、-3 dBFS のピークリミッター。NaN や無限大はそのブロックを無音にして数え、帰還する状態を消し、画面に NAN と回数を出す。プレビューの MASTER は -18 dB から始まる。
- **手を録って回す**: REC でつまみ・鍵・圧力・ボタンを時刻つきで録り（4096 イベント）、もう一度でループ再生する。ループの上から手で重ねられる。値ではなく動きを録るので、系の状態が変われば同じ動きでも違う結果になる。
- **画面**: 数値が主役の測定器の画面。7 行（エンコーダー 1 つに 1 行）、プロジェクトごとの図、出力・GR・身体のメーター。同じ 5×7 のピクセルフォントで描くので、プレビューと実機で同じ画面になる。

## 批判と穴

1. **規則を書いたのは結局わたし（Claude）だ。** 「数学を道具の性格として手に返す」と言っても、規則の空間そのもの（どの写像、どの帯、どの勢い）は設計者が固定しています。peeq の批判の向きで言えば、理論の層は消えたのではなく、見えにくい場所に移っただけかもしれません。手が規則を変えられるのは、用意した範囲の中だけです。
2. **「シンプルから複雑へ」は、それ自体が目的論で、ビルドアップの決まり文句に近い。** 依頼の中心なので全部に入れましたが、平均化の別の形になる危険があります。HOME、静止で落ち着く SEN、逆に応答する FELDMAN、PMVRS の S は、その逆向きを置くためのものです。それでも足りないかもしれません。
3. **1/f もカオスの縁も、長く聴けば統計的な規則性になる。** 完全なカオスより遅いだけで、いずれ「いつものあの揺れ」として平均化される可能性はあります。戻らない変化（SEN、HENKA、FELDMAN の crippling）は、それに抗うための記憶ですが、記憶が満ちれば同じことが起きます。
4. **28 種類の音源（キック、エレピ、ベル、パッド…）は、依頼文が避けたかった「既製の音色」そのものに近い。** 同じ連続空間の点にして、ロックや変異で離れていけるようにしましたが、名前のついた出発点はジャンルの典型を呼び込みます。HENKA は 1 ステップ目のキックから始まるので、4 つ打ちに引き寄せられる重力もあります。音源を選べることと、ありがちな音程で既製の音色を鳴らすことの間の線は、使い方の側に残っています。名前のない中間点を出発点にするモードが、次の一手として考えられます。
5. **PMVRS は、時間を分類した時点で西洋的な分析のモデルに戻っている可能性がある。** とくに P は機械的なグリッドそのものです。「リズムは奏者の動作に依存するので原始的なままになりがち」という指摘にも、半分しか答えていません。逃げ道は、切り替えが身体から来ることと、R が押し込みそのものであることだけです。
6. **ページ送りは「回した瞬間に変わる」と矛盾する。** 崩しは 6 ページあります。ページをボタンに置いて一押しで開けるようにし、白鍵の押し込みでページに関係なく各軸を壊せるようにして緩和していますが、K1〜K4 の意味がページで変わることは残っています。
7. **数値を見つめると、聴くことから引き離される。** 画面を消す（数値を出さない）モードはまだありません。
8. **手の録音は値ではなく動きを録る。** 意図どおりですが、同じループが毎回違う結果になるので、驚くかもしれません。
9. **技術的な穴**: USB オーディオを崩す元にすることは、fm1-base ではまだできません（INSTALL.md の 7）。実機での CPU 負荷は未測定です（HENKA の 4 声 × 3 オペレーター、キックのピッチ計算はサンプルごとの指数関数）。実機の鍵の圧力の幅と、プレビューのドラッグの圧力は感じが違うはずです。
10. **実機で分かったこと（推定を含む）**: 減衰していく掛け算（エンベロープ、フィルター、手の速さの記憶）は、数秒で非正規化数（denormal）に落ちる。x86 で数えると、変化は音のブロックの約 80% で非正規化数を計算していた。fm1-base が自分のフィルターでこれを避けている（`fm_flush`）ことから、FM-1 の FPU では遅いと推定し、全部 0 に落とすようにした（変化の負荷はホストで 1.4% → 0.9%）。「同じ音が鳴ってから鳴らなくなる」「つまみが効かない」は処理落ちの症状と合うが、実機での確認はまだ（画面右下の C と X で見える）。もう一つ、プレビューのマウスはつまみ 1 目盛りを 6 ピクセルで送るので、実機のクリックより 3〜4 倍速く読まれていた。調整はプレビューでしたので、実機では手の速さを 3 倍に読む。
11. **「静止の後に動く」は手全体の静止でなければならなかった。** つまみごとに静止を数えていたので、A を回しながら B に触れると「長い静止の後の動き出し」になり、崩しでは音が一瞬切れた。今は手全体の静止だけを数える。
12. **流転の「聴く」はステップの集合しか聴いていない。** 繰り返しの度合いは、どのステップが鳴ったかの一致で、音色（ロックや MORPH）の変化は聞こえていない。だから音色を変えるオペレーターは、必要と関係なく「中立」に近い。音色の変化も聴くには、ブロックごとの特徴（明るさなど）を小節ごとに比べる必要がある。また、オペレーターの種類ごとの傾き（OP_ORDER）は手で決めた値で、系がそれを学ぶわけではない。
13. **「斜に構える」は数値では作れない。** 流転のディープハウスの響きは、出発点として埋め込んだ 4 つの和音です。そこから奇数比でずれていくことで「まんま」にならないようにしていますが、どこで「ヘンテコ」になり、どこで「誠実」になるかは、聴いて CHORD と ORDER を回す人の側にあります。
