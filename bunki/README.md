# bunki 分岐 — 写像の数が聞こえる FM-1 のシンセ

鍵盤を 1 音押すと、最初は純音。R を回すと、その 1 音がロジスティック写像の分岐をたどる。写像の **数** がそのまま音の形になる:
不動点では純音、周期 2 で 2 音の往復、4 で 4 音の型、8 で 8 音の型、カオスで戻ってこない線と、1 本のサイン波が雲に裂けること、
周期 3 の窓で突然 3 音の型。鍵ごとのサイン波どうしは引き合い(ε)、1 本にまとまる・2 群に分かれる・群が組み替わり続ける・
ばらばらになる。HOLD で伸ばし、CHOP で写像が刻むリズムやアルペジオにし、EVOLVE で R が自分で分岐を登って崩れる。

M-VAVE FM-1(JieLi AC791N)の fm1-dock モジュール。**FM-1 に入れるファイルは [`fm1/bunki.dock`](fm1/bunki.dock)**、
入れ方・操作・元に戻す手順は [fm1/README.md](fm1/README.md)。エンジンはデスクトップでも動き、テストはそちらで回す。

## しくみ(詳しくは [DESIGN.md](DESIGN.md))

**ジェスチャー層**(FM-1 の既定):1 音 = N 本のサイン波。どれも自分の写像を持ち、1 本のステップの時計で全部いっせいに
1 歩進む(Kaneko の結合写像:時計が 1 本なので、時計どうしの比から来る型はない)。歩くたびに、写像の不動点からの距離 ×
CENTS の音程へ弧を描いて滑る。各サイン波の R は髪の毛ほど(2^-30)ずつ違う:周期の中では同じ音程にまとまり、カオスに入ると裂ける。

**音色の層**(最初の版、TIMBRE):

- 各ボイスは自分の基本周期ごとに写像を 1 回反復する(`x_k = R x (1 - x)`)。
- 写像の **差分** `d_k = x_k - x_(k-1)` を 2 オペ FM のモジュレータ・インデックスにする。
  不動点では d = 0 なので純音、周期 p の軌道は周期 p のまま音になる。
- モジュレータは毎周期キャリアに同期(比は整数 1..3 のみ)。基本波形の周期が T0 ちょうどなので、
  **聞こえる周期 = 写像の周期 × T0** が厳密に成り立つ。
- 複雑さの源は非線形性だけ。乱数は使わない(初期値も seed から写像自身で作る)。
- 整数演算のみ(x は 64 bit 固定小数点 Q62、64 bit 除算なし)。同じ seed と同じイベント列なら、
  どのコンパイラ・最適化でも同じビットが出る。

| 経路 (`path`) | 何が分岐するか |
|---|---|
| `map` | 写像 → インデックス(既定) |
| `fbt` | 1 周期前の自分の出力を位相に戻す。各位相点が `w' = sin(θ + βw)` を周期ごとに反復する |
| `both` | 両方。`C > 0` で協調(相互励起)、`C < 0` で競合(相互抑制) |
| `fb1` | DX7 型の 1 サンプル遅れフィードバック。**対照群**(段を踏まずにノイズへ行くことを示すため) |

操作:`u`(R のノブ位置 0..22。1 単位 = 倍化 1 段に伸縮済み)、`D`(R の自己移動)、
`eps`(ボイス間の大域結合)、`C`、`lift`(`sqrt` で深い段を持ち上げる)、`ratio`、`gain`。

## 動かし方

```sh
cd bunki
make            # build/bunki(ツール)と build/bunki_test
make test       # テスト一式(tests/last_report.txt)と、3 コンパイラでのビット一致確認
make demo       # build/demo/ に WAV と画面(PPM)
build/bunki sweep 60 60 out.wav gesture       # C4 を鳴らしたまま、R を 2.5 から 4.0 まで 60 秒で(map なら音色の層)
build/bunki run tests/scripts/gesture.txt out.wav   # ジェスチャー層をひととおり(2 分)
build/bunki run tests/scripts/stages.txt out.wav --screens dir --csv tele.csv
build/bunki blind 7 blind.wav key.txt         # ブラインド聴取用(順番は seed から写像で決まる)
```

台本は `<ミリ秒> <コマンド> [引数]`。時刻は 256 フレームのブロック(FM-1 の 1 回分)に丸め、
ブロックの頭でファイル順に適用する。書式は `host/bunki_cli.c` の先頭。

## 構成

```
core/bunki.h, bunki.c   エンジン(プラットフォーム非依存、整数のみ)
core/bk_tables.h        サイン表・log2 表(tools/gen_tables.py が生成)
host/bunki_cli.c        台本 → WAV / テレメトリ CSV / 画面
host/bk_screen.c        FM-1 の画面(240×240)をデスクトップで描く
tests/bunki_test.c      判定基準の数値(58 チェック)
tests/scripts/          perform.txt(全機能)、stages.txt(段ごとに止まる)
fm1/bunki/              fm1-dock のモジュール(bunki_module.c, module.cfg)
fm1/bunki.dock          ビルド済み(fm1/build.sh で作り直せる)
fm1/sim/sim.c           fm1-dock のふりをする偽ホスト(make fm1sim)
```

## いまの結果(`make test`、全 71 チェック通過)

**ジェスチャー層**

| | |
|---|---|
| 写像の周期 = 聞こえる型 | 1 本・8 回/秒・跳ぶ:音から測った型の長さが 1, 2, 4, 8、窓で 3、カオスで繰り返しなし(写像の周期と一致)。周期 4 の型は +159 / −301 / +224 / −461 セント |
| 純音から始まる | 4 本・R 2.75:1 本のサイン波(線の外 −65 dB) |
| サイン波の網(8 本・R 4) | ε 0:7.2 群 / ε 0.3:2 群でほぼ動かない / ε 0.4:3.8 群、毎秒 8.7 回組み替わる / ε 0.5 以上:1 本。輪(隣どうし)では ε 0.6 でも 3.8 群 |
| 裂ける | R 3.9、6 本が 1 つの音程から 2 秒(16 歩)で裂ける |
| 覚えている | 周期 2 の 1 本の往復が、カオスを通って戻ると、逆向きの 2 本の往復(和音)になって残る |
| EVOLVE | ノブ u 0.5 から R 4 まで 49 秒で登り、周期 3 の窓に同じ幅のカオスの 6 倍(22.5 秒)留まり、102 秒でノブまで戻る |
| HOLD / CHOP | 離した鍵が鳴り続け、HOLD を切ると止む / 周期 4 の GATE は `x.x.` を刻み、ARP はカオスの中で `1334441413242342` と弾く |

**音色の層**(最初の版のまま)

| 基準 | 結果 |
|---|---|
| 周期倍の段が数えられる | C4 と G5 で、写像の周期 = 音から検出した周期 = 1, 2, 4, 8, 16 |
| カオスの中に窓 | 周期 3 の窓が R 3.82845(理論値 1+√8 = 3.82843)から。非周期成分がカオスの −5 dB から窓で −82 dB へ |
| 再現性 | 同じ seed とイベントで同一ハッシュ。gcc −O0 / gcc −O2 / clang −O2 で同一 |
| 有限精度 | 30 bit のカオスは 89〜13,404 反復でループに落ちる。エンジンの 64 bit では 2^25 反復(C4 で 36 時間)の中にループなし |
| 同期の理論 | 同じ音高の 4 ボイス(R 4)は ε 0.45 で 0 %、0.55 で 100 % 同期(理論値 0.5) |
