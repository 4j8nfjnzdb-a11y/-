# bunki 分岐 — 1 音が分岐図を歩く FM エンジン

鍵盤を 1 音押すと、最初は純音。R を回すと、その 1 音がロジスティック写像の分岐をたどって
純音 → 周期 2(1 オクターブ下)→ 周期 4 → 周期 8 → … → カオス(倍音のまわりのノイズの帯)→
周期 3 の窓で突然澄む → 再びカオス、と変わっていく。

M-VAVE FM-1(JieLi AC791N)の fm1-dock モジュール。**FM-1 に入れるファイルは [`fm1/bunki.dock`](fm1/bunki.dock)**、
入れ方・操作・元に戻す手順は [fm1/README.md](fm1/README.md)。エンジンはデスクトップでも動き、テストはそちらで回す。

## しくみ(詳しくは [DESIGN.md](DESIGN.md))

- 各ボイスは自分の基本周期ごとに写像を 1 回反復する(`x_k = R x (1 - x)`)。
- 写像の **差分** `d_k = x_k - x_(k-1)` を 2 オペ FM のモジュレータ・インデックスにする。
  不動点では d = 0 なので純音、周期 p の軌道は周期 p のまま音になる。
- モジュレータは毎周期キャリアに同期(比は整数 1..3 のみ)。基本波形の周期が T0 ちょうどなので、
  **聞こえる周期 = 写像の周期 × T0** が厳密に成り立つ。
- 複雑さの源は非線形性だけ。乱数は使わない(初期値も seed から写像自身で作る)。
- 整数演算のみ(x は 64 bit 固定小数点 Q62、64 bit 除算なし)。同じ seed と同じイベント列なら、
  どのコンパイラ・最適化でも同じビットが出る。

| 経路 (`path`) | 何が分岐するか |
|---|---|
| `map` | 写像 → インデックス(既定) |
| `fbt` | 1 周期前の自分の出力を位相に戻す。各位相点が `w' = sin(θ + βw)` を周期ごとに反復する |
| `both` | 両方。`C > 0` で協調(相互励起)、`C < 0` で競合(相互抑制) |
| `fb1` | DX7 型の 1 サンプル遅れフィードバック。**対照群**(段を踏まずにノイズへ行くことを示すため) |

操作:`u`(R のノブ位置 0..22。1 単位 = 倍化 1 段に伸縮済み)、`D`(R の自己移動)、
`eps`(ボイス間の大域結合)、`C`、`lift`(`sqrt` で深い段を持ち上げる)、`ratio`、`gain`。

## 動かし方

```sh
cd bunki
make            # build/bunki(ツール)と build/bunki_test
make test       # テスト一式(tests/last_report.txt)と、3 コンパイラでのビット一致確認
make demo       # build/demo/ に WAV と画面(PPM)
build/bunki sweep 60 60 out.wav map           # C4 を鳴らしたまま、ノブを 0 から 22 まで 60 秒で
build/bunki run tests/scripts/stages.txt out.wav --screens dir --csv tele.csv
build/bunki blind 7 blind.wav key.txt         # ブラインド聴取用(順番は seed から写像で決まる)
```

台本は `<ミリ秒> <コマンド> [引数]`。時刻は 256 フレームのブロック(FM-1 の 1 回分)に丸め、
ブロックの頭でファイル順に適用する。書式は `host/bunki_cli.c` の先頭。


## いまの結果(`make test`、全 58 チェック通過)

**判定基準**

| 基準 | 結果 |
|---|---|
| 周期倍の段が数えられる | C4 と G5 で、写像の周期 = 音から検出した周期 = 1, 2, 4, 8, 16。各段で新しく現れる成分:p2 −9 dB、p4 −15 dB、p8 −27 dB、p16 −37 dB(全エネルギー比)。周期外の成分は −80 dB 前後 |
| カオスの中に窓 | 周期 3 の窓が R 3.82845(理論値 1+√8 = 3.82843)から。非周期成分がカオスの −5〜−6 dB から窓で −82 dB へ。周期 5、6 の窓も検出 |
| 再現性 | 同じ seed とイベントで同一ハッシュ。gcc −O0 / gcc −O2 / clang −O2 で同一。UBSan / ASan でも同一 |
| 画面 | 分岐図(伸縮済みの横軸)、現在位置、各ボイスの直近 64 点、周期(四角の数)、λ のバー |
| 指標 | 周期の検出値、Lyapunov 指数(倍精度の参照値と 0.006 以内) |

**測って分かったこと(チェックではなく測定)**

- 30 bit 固定小数点のカオスは 89〜13,404 反復で周期軌道に落ちる(R=3.95 で 89 反復 = C4 で 0.34 秒のループ)。
  エンジンの 64 bit では 2^25 反復(C4 で 36 時間)の中に周期は見つからない。
- 同じ音高の 4 ボイス(R=4)は、理論どおり ε > 0.5 で同期(0.45 で 0 %、0.55 で 100 %)。
- 音高の違うボイスは更新が同時でないので Kaneko の GCM そのものではない。**更新タイミングの漏れは実在する**:
  周期 2 の領域で 5 度の 2 音を弱く結合すると(ε 0.05〜0.2)写像が非周期になり、周期外成分が −30〜−35 dB 出る。
- 6 音を強く結合(ε 0.7)すると、全ボイスが不動点に落ちて純音になる(振動の消滅)。音を増やすと澄む。
- 経路の比較(C4、−40 dB を超えたらその段):

  | 経路 | p2 | p4 | p8 | 非周期 | 窓 |
  |---|---|---|---|---|---|
  | map | u 1.00 | 2.00 | 3.25 | 6.25 | p6, p3, p5 |
  | fbt | 1.25 | 2.25 | 3.00 | 6.25 | (0.25 刻みでは見つからず) |
  | both C=0 | 1.00 | 1.50 | 1.75 | 2.00 | なし |
  | both C=+1 | 0.75 | 1.50 | 1.75 | 1.75 | なし |
  | both C=−1 | 1.25 | 1.50 | 1.75 | 1.00 | 周期 14, 16 が一時的に |
  | fb1 (DX7) | 12.25 | 12.00 | 11.75 | 12.50 | なし |

  2 経路を合わせるとカスケードが縮み(u 1〜2 に詰まる)、段は数えにくくなる。
  DX7 型は p2/p4/p8 がカオスの入口でまとめて出る(段を踏まない)。
- `D` の歩行は、手の位置によらず **カオスの縁(u 4〜6)のまわりに集まる**。
  D=0.5 で u 3〜7、D=1 で u 2〜12 を行き来する。手の R はほとんど効かない。
